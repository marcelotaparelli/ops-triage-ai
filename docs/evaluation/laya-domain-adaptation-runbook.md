# Laya Experiment B execution runbook

This runbook is for a CUDA host with at least 14 GiB VRAM. It uses the committed Experiment B data and code; no command below trains or selects on the frozen 70-ticket held-out. Use a repository checkout containing the Experiment B commits. Because this work is not pushed, transfer those commits through a local Git bundle or another approved artifact transfer if the GPU host is remote; do not substitute a stale public clone. The model download requires Internet access and the pinned Hugging Face revision. Keep credentials out of the checkout and artifacts.

1. Create a separate Python environment with a CUDA-enabled PyTorch build compatible with the host driver. Install `scripts/laya-adapt-gpu-requirements.txt` into it. Before running, verify `torch.cuda.is_available()` and record `nvidia-smi`. The training artifact records the actual Torch/CUDA/driver versions, GPU, VRAM and CPU/RAM; the repository's CPU `scripts/laya-requirements.txt` is for Experiment A and is not a GPU training environment.
2. Verify the dataset using `python scripts/laya_adapt_dataset.py --check`. The TRAIN/VALIDATION hashes are pinned in `scripts/laya-adapt-training-config.json`. The loader also checks the unchanged Experiment A question-config hash and the pinned base checkpoint weight hash.
3. On the GPU host, run `python scripts/laya_adapt_train.py --output-dir <new-output-directory>`. The directory must not exist. The trainer refuses CPU and low-VRAM execution, saves `epoch-1` through `epoch-4`, and records loss, wall time, peak CUDA memory, sampled GPU utilization, hardware, settings and checkpoint hashes in `training.json`. Its 3,600-second training cap does not replace a cloud-provider billing cap. If the run fails, preserve `training.json` and the partial checkpoint directory; do not silently relabel a retry as the original run.
4. Copy `training.json` to `artifacts/laya-adapt-training.json`. For each epoch `N=1..4`, run `python scripts/laya_adapt_eval.py --mode candidate-validation --checkpoint-dir <new-output-directory>/epoch-N --epoch N --artifact artifacts/laya-adapt-validation-epoch-N.json`. These are VALIDATION-only passes. The base checkpoint's separate canonical validation result is `artifacts/laya-adapt-base-validation.json`.
5. Run `python scripts/laya_adapt_select.py`. It requires four complete candidate artifacts and chooses the epoch using the predeclared exact-tuple, macro-F1, mean Brier, earliest-epoch rule. Copy the selected checkpoint into local `.cache/laya-adapt-selected` without changing its files. Run `python scripts/laya_adapt_eval.py --mode selected-train --checkpoint-dir .cache/laya-adapt-selected --epoch N --artifact artifacts/laya-adapt-selected-train.json` on the GPU host to measure the TRAIN side of the generalization gap.
6. Bring the selected checkpoint and validation/training artifacts into the final checkout. Run the full repository gates, inspect the results, then commit all preparation and validation artifacts. `git status --porcelain` must be empty before freeze. Run `python scripts/laya_adapt_heldout.py freeze`; inspect and commit `artifacts/laya-adapt-freeze.json` as **Freeze 2**.
7. Only after that committed freeze, run `python scripts/laya_adapt_heldout.py heldout` **once** on the same checkout, with `.cache/laya-adapt-selected` present. The runner requires a clean tree, rechecks all artifact/data/code/checkpoint hashes, reserves a separate result and attempt journal, and refuses automatic retries. It performs sequential CPU inference to match Experiment A's local device. Record any operational failure before deciding whether a rerun is technically justified.

Neither the trainer nor candidate evaluator reads `datasets/triage-eval.jsonl`. The freeze and official held-out runner alone verify/open that file. The Experiment A files `artifacts/laya-held-out.json`, `artifacts/laya-held-out-attempts.jsonl`, and its reports remain untouched. Do not run the held-out command to test installation or debugging.
